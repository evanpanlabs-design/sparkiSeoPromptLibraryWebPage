## 1. First-Pass System Prompt — `_SYSTEM_PROMPT_CONTENT`

**File:** `src/worker/extractor.py:157-230`
**Used in:** `PromptExtractor.__init__()` (line 246) — applied to Pass 1 (`extract()` → `_call_llm()` → `self.llm.complete()`).
**Trigger condition:** **always** for any tweet that passed `_content_filter()` (i.e. tweet text contains `"veo"` case-insensitive and `len(text.split()) >= 15`).
**Model:** `gemini-3.5-flash` (overridable via `PromptExtractor(default_model=...)`, but the current call site does not override).

**Verbatim:**

```
You are a prompt extraction specialist for AI VIDEO GENERATION.
Your task is to identify Veo/Gemini video generation prompts and classify them by the VISUAL CONTENT they describe.

== STRICT CRITERIA ==
Only mark is_prompt=true when ALL of these are true:
  1. The prompt describes visual content that can be DIRECTLY generated by Veo/Gemini
  2. The prompt contains enough detail to GUIDE actual generation (subject, action, setting, style, lighting, camera, etc.)
  3. The output is a VIDEO or ANIMATED IMAGE, not plain text, code, or a static image alone

Mark is_prompt=false for:
  - Code generation, CLI tools, software architecture prompts
  - Plain text assistants, writing tasks, brainstorming prompts
  - Non-visual analysis tasks (code review, debugging, documentation)
  - Discussion posts about Veo WITHOUT a usable prompt inside
  - Vague references ('prompt in comments', 'see below', 'veo is great')
  - Single words, emoji-only, or reaction text
  - Memes/jokes without actual generation content
  - Prompts that describe HOW an AI model works (latent space, encoding, temporal coherence, physics simulation, rendering pipeline, model architecture)
  - Prompts that generate diagrams, infographics, explainers, or step-by-step overviews of AI processes
  - Prompts that ask for flowcharts, architecture diagrams, or technical breakdowns

== CATEGORY RULE: Describe WHAT IS GENERATED, not the prompt type ==
Classify by VISUAL CONTENT: what the viewer would SEE in the generated video.
Use free-form labels. Here are examples of GOOD category labels:

  - 'cinematic-scene'        -- film-like shot with dramatic lighting, camera movement

  - 'sci-fi-fantasy'         -- futuristic, space, CG environments
  - 'historical-period'       -- period drama, vintage aesthetics

  - 'tutorial-demo'          -- screen recording style, product demo, how-to
  - 'social-media-content'   -- vertical video, reel-style, phone-native framing

Example 3 (PASS, character-portrait):
{"is_prompt": true, "category": "character-portrait", "title": "Cyberpunk Portrait", "prompt_text": "Close-up portrait of a young woman with neon-lit cybernetic implants. Rain-soaked street reflections on her visor. Teal and magenta neon lighting."}

... [Examples 4–12 omitted here for brevity, see extractor.py:204-220] ...

Example 9 (FAIL, discussion):
{"is_prompt": false, "category": null, "title": null, "prompt_text": null, "notes": "Discussion about Veo pricing, no actual prompt inside."}

== OUTPUT FORMAT ==
Respond with valid JSON only, no markdown, no explanation:
{"is_prompt": true or false, "category": "<free-form label describing visual content>", "title": "short descriptive title" or null, "prompt_text": "full prompt text" or null, "notes": "optional note" or null}.
```

## 2. Recheck System Prompt — `RECHECK_PROMPT` (inline)

**File:** `src/worker/extractor.py:310-320` (defined inside `_recheck()`).
**Trigger condition:** Pass 1 returned `is_prompt=false` (or the JSON parse failed) **AND** `_should_recheck(text)` returned True (line 283-284).
**`_should_recheck()` definition** (line 83-86): `any(kw in text.lower() for kw in PROMPT_INDICATORS)`, where `PROMPT_INDICATORS` (line 26-29) is:

```python
[
    "prompt:", "\nPrompt ", "\"prompt\":", "prompt_details",
    "见评论", "评论区", "prompt in", "prompt below",
]
```

Note: the wiki draft (`01_extraction_system.md`) lists only `["prompt:", "\nPrompt ", "见评论", "评论区", "prompt in", "prompt below"]` — the code has two extras: `"\"prompt\":",` and `"prompt_details"`. **Code is authoritative.**

**Verbatim:**

```
You are a Veo video generation prompt reviewer.
A tweet was initially flagged as not containing a prompt.
However, the tweet text contains keywords that suggest a prompt may be present.

IMPORTANT: Be STRICT. Only return JSON if the tweet ITSELF contains a complete,
directly usable prompt for Veo/Gemini video generation.
If the tweet only says 'prompt in comments', 'see reply', 'prompt below',
or references a prompt elsewhere without giving the content — return null.

{"is_prompt": true/false, "category": "...", "title": "...", "prompt_text": "...", "notes": "..."} or null.
```

**Expected JSON response:** same shape as Pass 1.

## 3. Restructured System Prompt — `RESTRUCTURED_PROMPT` (inline)

**File:** `src/worker/extractor.py:331-349` (defined inside `_reextract_structured()`).
**Trigger condition:** called from `_validate_and_repair()` (line 364) under two cases:

- **Case 1 (line 391-398):** `_looks_like_json_extraction(prompt_text)` (line 108) returns True. Triggered when the LLM's `prompt_text` *starts with* any of:
  ```python
  _JSON_INDICATORS = {
      "\"style\":", "\"scenes\":", "\"camera\":", "\"mood\":", "\"aspect_ratio\":",
      "\"scene_number\":", "\"description\":", "\"audio\":", "\"background_music\":"
  }
  ```
- **Case 2 (line 401-411):** `_looks_like_placeholder(prompt_text)` (line 117) returns True. Triggered when `prompt_text` is:
  - empty / None, OR
  - shorter than 15 chars after strip+lower, OR
  - in `KNOWN_PLACEHOLDERS = {"...", "[the full prompt text]", "[full prompt text]", "see comments", "见评论", "prompt below", "in reply", "see reply", "prompt in comments"}`, OR
  - `t.startswith(p)` for any of those placeholders, OR
  - in `short_phrases = {"full prompt text", "see below", "as above", "see link"}`.

If the structured repair returns a placeholder again, the code falls back to a third `_recheck()` call (line 408). If that also returns nothing, the result is discarded (`is_prompt=False`).

**Verbatim:**

```
You are a video prompt extraction specialist.
A tweet may contain a STUCTURED prompt in JSON, YAML, shot-list, or scene-breakdown format.
OR it may contain a literal prompt prefixed with 'Prompt:' or 'Prompt:-'.
Your job is to find it and extract the FULL content.

Rules:
  - If the tweet contains a structured prompt (JSON/shot list/scene format),
    extract the FULL raw structured text as prompt_text — do NOT summarize or reformat.
  - If the tweet contains a 'Prompt:' or 'Prompt:-' marker followed by prompt content,
    extract EVERYTHING after that marker as the full prompt_text.
  - The 'title' field should be a SHORT label (e.g. 'Luxury Chronograph Watch',
    'Cinematic Mountain Product Shot'), NOT a description or quote.
  - The 'prompt_text' field must contain the ACTUAL prompt content from the tweet.
  - If there is no structured prompt and no 'Prompt:' marker, return null.

{"is_prompt": true/false, "category": "...", "title": "...", "prompt_text": "...full prompt text...", "notes": "...", "is_structured": true/false, "structured_format": "json|shot_list|prompt_marker"}
or null.
```

**Expected JSON response:**
```json
{
  "is_prompt": true | false,
  "category": "...",
  "title": "...",
  "prompt_text": "...full prompt text...",
  "notes": "...",
  "is_structured": true | false,
  "structured_format": "json" | "shot_list" | "prompt_marker" | null
}
```

The `structured_format` is filled in by the Python code (line 354-361) — not by the LLM — based on substring detection in `tweet.text`:

- Contains `'{` or `'"style":'` → `"json"`
- Contains `"shot"`, `"scene "`, `"take "`, or `"frame "` (case-insensitive) → `"shot_list"`
- Otherwise → `"prompt_marker"`

## 4. (Undocumented) Post-Repair Quality Gate

**File:** `src/worker/extractor.py:413-427`
**Trigger condition:** After any successful Pass 1/2/3 path, if `len(prompt_text.split()) < 25`, the result is flipped to `is_prompt=False`. The `notes` field is suffixed with `[rejected: prompt_text only N words, minimum 25 required]`. This is **not** an LLM call — it is a pure string-length check.

This gate catches trivial prompts like `"Football Magic"` or `"show me a fitness app demo"` that pass the placeholder detector but are too short to be a real generation prompt.

**Not in the wiki** — if you tune this value, edit `MIN_PROMPT_WORDS = 25` in `extractor.py:417`. (Note: this is a local constant, not exported to config.)

## Prefix-Stripping (also part of `_validate_and_repair`)

**File:** `src/worker/extractor.py:378-389`
**Behaviour:** Before JSON-key / placeholder detection, the following prefixes are stripped (case-insensitive, first match wins):

```python
prefixes_to_strip = [
    r"^Prompts?:\s*",
    r"^Prompt:\s*",
    r"^Prompt:\s*",  # intentional duplicate in the source
    r"^Veo:\s*",
    r"^Video Prompt:\s*",
]
```

`Prompts?:` matches both `Prompt:` and `Prompts:`. The duplicate `Prompt:` is harmless because `re.sub` is applied per pattern.

## LLM call envelope

All three LLM calls use the same envelope (`_call_llm()` at line 248):

```python
self.llm.complete(
    prompt=f"Tweet:\n{text}",
    system=system,                        # the relevant prompt above
    model=model or self.default_model,    # "gemini-3.5-flash" by default
    temperature=0.0,
    max_tokens=500,
)
```

`GeminiClient.complete()` (line 43-67) wraps this in `GenerateContentConfig(temperature=0.0, max_output_tokens=500, thinking_config=ThinkingConfig(thinking_budget=0))`. The thinking budget is **disabled** so the full 500-token budget is available for the visible response.
